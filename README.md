# PSMacc — โปรแกรมบัญชีออนไลน์สำหรับธุรกิจไทย

เว็บแอปบัญชีแบบไฟล์เดียว (HTML + JavaScript ล้วน ไม่ต้องมีเซิร์ฟเวอร์)

## ความสามารถหลัก
- เอกสารขาย/ซื้อ: ใบเสนอราคา ใบสั่งขาย ใบแจ้งหนี้ ใบเสร็จ ใบลดหนี้ ใบวางบิล บิลซื้อ ค่าใช้จ่าย เช็คจ่าย
- ลงบัญชีคู่อัตโนมัติ สมุดรายวัน แยกประเภท งบทดลอง งบกำไรขาดทุน งบดุล และรายงานมาตรฐาน 80+ รายงาน
- ภาษี: ภ.พ.30 (VAT รอเรียกเก็บสำหรับค่าบริการ), หัก ณ ที่จ่าย, หนังสือรับรอง 50 ทวิ
- ธนาคาร: บัญชีหลายบัญชี, กระทบยอด, นำเข้า Statement (CSV/Excel/PDF) และจับคู่อัตโนมัติ
- ปิดงบรายเดือน, ยอดยกมาจากงบปีก่อน, หลายบริษัท/หลายสาขา, โครงการ/แผนก
- พิมพ์/PDF ฟอร์มเอกสาร (ต้นฉบับ/สำเนา), แนบไฟล์, อ่านใบเสร็จด้วย OCR (Tesseract)
- นำเข้า/ส่งออกข้อมูล Excel

## การเก็บข้อมูล
- ตั้งค่า **Firebase** แล้ว (ดูหัวข้อถัดไป): ต้องเข้าสู่ระบบ ข้อมูลเก็บบน Firebase ใช้ร่วมกันได้หลายคนจากทุกเครื่อง
- เปิดเป็น **Claude Artifact**: ข้อมูลเก็บในฐานข้อมูลของ Artifact ใช้ร่วมกันได้หลายคน
- เปิดเป็น **ไฟล์/GitHub Pages**: ข้อมูลเก็บใน localStorage ของเบราว์เซอร์เครื่องนั้นเท่านั้น
  ควรสำรองข้อมูลสม่ำเสมอ (ฟันเฟือง → สำรองข้อมูลบริษัท) และฟีเจอร์แนบไฟล์/อ่านเอกสารด้วย Claude ใช้ไม่ได้ในโหมดนี้

## ระบบ Login (Firebase)
เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน แต่ละบริษัทมีสิทธิ์ผู้ใช้ดังนี้
- **เจ้าของหลัก**: ผู้สร้างบริษัท มีสิทธิ์สูงสุด ไม่มีใครลดสิทธิ์หรือนำออกได้ เปลี่ยนได้ด้วยการ **โอนสิทธิ์เจ้าของหลัก** เท่านั้น (ต้องพิมพ์อีเมลผู้รับเพื่อยืนยัน)
- **เจ้าของ**: ทำได้ทุกอย่าง รวมถึงเชิญผู้ใช้และกำหนดสิทธิ์ (ยกเว้นเจ้าของหลัก) แต่ลบบริษัทหรือโอนสิทธิ์เจ้าของหลักไม่ได้
- **ผู้แก้ไข** (ฝ่ายบัญชี): สร้างและแก้ไขเอกสารและข้อมูลบัญชี รวมถึงข้อมูลใช้งานประจำวันของบริษัท แต่แก้ข้อมูลนิติบุคคลหลักไม่ได้
- **ผู้ดู**: ดูข้อมูลและรายงานได้อย่างเดียว

| ข้อมูล / การกระทำ | เจ้าของหลัก | เจ้าของ | ผู้แก้ไข (ฝ่ายบัญชี) | ผู้ดู |
|---|:-:|:-:|:-:|:-:|
| ข้อมูลนิติบุคคลหลัก: ชื่อบริษัท, ชื่อจดทะเบียน, เลขผู้เสียภาษี, สถานะ VAT, ประเภทนิติบุคคล, ที่อยู่ตามกฎหมาย, เดือนเริ่มรอบบัญชี | ✅ | ✅ | ❌ | ❌ |
| ข้อมูลใช้งานประจำวัน: ที่อยู่บนเอกสาร, โทร, อีเมล, เว็บไซต์, โลโก้, ข้อมูลติดต่อลูกค้า, ค่าเริ่มต้นเอกสาร/รายงาน | ✅ | ✅ | ✅ | ❌ |
| สาขา: เพิ่ม, แก้ชื่อ/ที่อยู่/โทร, ปิดใช้งาน/เปิดใช้งาน | ✅ | ✅ | ✅ | ❌ |
| สาขา: แก้รหัสหรือลบ สาขาที่ยังไม่มีประวัติ | ✅ | ✅ | ✅ | ❌ |
| สาขา: ลบสาขาที่มีประวัติ (รหัสสาขาที่มีประวัติแก้ไม่ได้ ใช้ปิดใช้งานแทน) | ✅ | ✅ | ❌ | ❌ |
| งวดบัญชี: ล็อกงวด (เลื่อนวันล็อกไปข้างหน้า) | ✅ | ✅ | ✅ | ❌ |
| งวดบัญชี: ปลดล็อก / ถอยวันล็อก | ✅ | ✅ | ❌ | ❌ |
| เชิญ/เปลี่ยนสิทธิ์/นำผู้ใช้ออก, ดูประวัติ (Audit Log) | ✅ | ✅ | ❌ | ❌ |
| โอนสิทธิ์เจ้าของหลัก, ลบบริษัท | ✅ | ❌ | ❌ | ❌ |

"สาขาที่มีประวัติ" คือสาขาที่มีเอกสาร (ใบกำกับภาษี ใบเสร็จ บิล ฯลฯ) อ้างอิงแล้ว ระบบทำเครื่องหมายให้อัตโนมัติเมื่อบันทึกเอกสาร และยกเลิกไม่ได้
การล็อก/ปลดล็อกงวดและการลบสาขาทุกครั้งถูกบันทึกในประวัติ พร้อมผู้ทำ วันเวลา และงวด/สาขา

**งวดบัญชีที่ล็อกแล้ว** บังคับที่ `firestore.rules` (ยิงตรงเข้า Firestore ก็ไม่ได้) สำหรับทุกบทบาท รวมถึงเจ้าของ:
เอกสารและแบบ ภ.พ.30 ที่ลงวันที่ในงวดที่ล็อก (วันที่ ≤ วันล็อก) สร้าง แก้ไข ยกเลิก ลบ หรือย้ายวันที่เข้า/ออกไม่ได้ ต้องให้เจ้าของปลดล็อกก่อน
ยกเว้นการรับ/จ่ายชำระที่ลงวันที่หลังวันล็อก ซึ่งบันทึกบนเอกสารเดิมได้ (เช่น รับชำระใบแจ้งหนี้เดือนที่ปิดแล้ว)
การชำระที่ลงวันที่ในงวดที่ล็อกเพิ่ม/ลบไม่ได้ ข้อจำกัด: ขณะมีการล็อก การเขียนหนึ่งครั้งเพิ่ม/ลบรายการชำระได้ไม่เกิน 10 รายการ
บังคับทั้งในหน้าเว็บและใน `firestore.rules`

ทุกการเปลี่ยนสิทธิ์ (สร้างบริษัท เข้าร่วมตามคำเชิญ เปลี่ยนสิทธิ์ นำออก โอนสิทธิ์) ถูกบันทึกใน **ประวัติการเปลี่ยนสิทธิ์**
พร้อมผู้ดำเนินการ ผู้ถูกเปลี่ยน สิทธิ์เดิม/ใหม่ และเวลาจากเซิร์ฟเวอร์ `firestore.rules` บังคับให้ทุกการเปลี่ยนแปลงต้องมีบันทึก
และบันทึกแก้ไขหรือลบไม่ได้ เจ้าของดูประวัติได้ที่ จัดการผู้ใช้

### ตั้งค่าครั้งแรก
1. สร้างโปรเจกต์ที่ https://console.firebase.google.com
2. **Authentication → Sign-in method** เปิด **Email/Password**
3. **Firestore Database → Create database** เลือก production mode
4. **Firestore Database → Rules** คัดลอกเนื้อหาไฟล์ `firestore.rules` ไปวางแทนของเดิม แล้วกด **Publish**
   (หรือใช้คำสั่ง `npx firebase-tools deploy --only firestore:rules --project <project-id>`)
5. **Project settings → Your apps → Add app (Web)** คัดลอกค่า `firebaseConfig` ไปใส่ใน `src/config.js` แล้วรัน `./build.sh`
6. ถ้าเผยแพร่บน GitHub Pages: **Authentication → Settings → Authorized domains** เพิ่ม `<ชื่อผู้ใช้>.github.io`

ค่าใน `src/config.js` เปิดเผยได้ ความปลอดภัยของข้อมูลมาจาก `firestore.rules` ต้อง Publish rules ทุกครั้งที่แก้ไฟล์นี้

### ไฟล์แนบ (Firebase Storage)
ไฟล์แนบของเอกสารเก็บใน Firebase Storage ที่ `companies/{บริษัท}/files/{id}` สิทธิ์ตาม `storage.rules`:
สมาชิกบริษัทเปิดดูได้, เจ้าของและผู้แก้ไขอัปโหลดได้ (รูปภาพ PDF CSV TXT JSON MD ไม่เกิน 20 MB), แก้ไขหรือลบไฟล์ไม่ได้ (เก็บเป็นหลักฐาน)
1. **Storage → Get started** (โปรเจกต์ใหม่ต้องใช้แพ็กเกจ Blaze จึงจะสร้าง bucket ได้ ยังมีโควตาใช้ฟรี) เลือก production mode
2. **Storage → Rules** คัดลอกเนื้อหาไฟล์ `storage.rules` ไปวางแล้วกด **Publish**
   ครั้งแรก Console จะขอสิทธิ์ให้ Storage อ่าน Firestore ได้ (ใช้ตรวจสมาชิกบริษัท) ให้กด Allow
   (หรือ `npx firebase-tools deploy --only storage --project <project-id>`)
3. ตรวจว่า `storageBucket` ใน `src/config.js` ตรงกับชื่อ bucket ในหน้า Storage
   แล้วเปลี่ยน `FIREBASE_STORAGE_ENABLED = true` ใน `src/config.js` และรัน `./build.sh` (ค่าเริ่มต้นเป็น `false` ปุ่มแนบไฟล์จะถูกซ่อน)
4. (ไม่บังคับ) ถ้าต้องการพรีวิว PDF/ไฟล์ข้อความในหน้าเว็บ ต้องเปิด CORS ของ bucket ด้วย Cloud Shell:
   ```
   echo '[{"origin":["https://<ชื่อผู้ใช้>.github.io"],"method":["GET"],"maxAgeSeconds":3600}]' > cors.json
   gcloud storage buckets update gs://<bucket> --cors-file=cors.json
   ```
   ถ้าไม่ตั้ง รูปภาพยังแสดงได้ ไฟล์อื่นจะมีลิงก์ "เปิดไฟล์ในแท็บใหม่" แทน

ถ้ายังไม่เปิด Storage (`FIREBASE_STORAGE_ENABLED = false`) ส่วนอื่นของแอปใช้งานได้ตามปกติ ปุ่มแนบไฟล์ถูกซ่อนและแสดงว่ายังไม่ได้เปิดใช้การแนบไฟล์

### การใช้งาน
- ผู้ใช้ใหม่สมัครสมาชิกแล้วสร้างบริษัทแรก ผู้สร้างเป็นเจ้าของบริษัท
- เจ้าของเชิญผู้ใช้จาก **ชื่อบริษัทมุมขวาบน → จัดการผู้ใช้** ระบบไม่ส่งอีเมลเชิญให้
  ต้องแจ้งผู้ใช้เองให้สมัครด้วยอีเมลที่เชิญและกดลิงก์ยืนยันอีเมล จากนั้นบริษัทจะปรากฏเมื่อเข้าสู่ระบบ
- ย้ายข้อมูลเดิมจากโหมดเบราว์เซอร์: ในโหมดเดิมใช้ ฟันเฟือง → สำรองข้อมูลบริษัท แล้วเข้าสู่ระบบ Firebase และใช้ กู้คืนจากไฟล์สำรองข้อมูล
- ผู้ดูเห็นข้อมูลแบบอ่านอย่างเดียว ปุ่มสร้าง/แก้ไข/ลบถูกซ่อน (และ firestore.rules ปฏิเสธการเขียนอยู่แล้ว)
- ข้อจำกัด: อ่านเอกสารด้วย Claude (OCR) ใช้ไม่ได้ในโหมดนี้, ไฟล์แนบที่กู้คืนเข้าบริษัทอื่นยังชี้ไปที่ไฟล์ของบริษัทเดิม (เปิดได้เฉพาะสมาชิกบริษัทเดิม),
  ทุกครั้งที่เปิดแอประบบจะอ่านข้อมูลทั้งบริษัท ควรตรวจสอบโควตาและค่าบริการของ Firebase เมื่อข้อมูลมาก

### นำเข้าสมุดรายวัน / GL
ตั้งค่า → นำเข้าข้อมูล → **Journal Entries (GL)** (หรือ ⚙ → นำเข้าข้อมูล → สมุดรายวัน / GL) รับไฟล์ CSV หรือ Excel
- 1 แถว = 1 บรรทัดบัญชี คอลัมน์: เลขที่รายการ, วันที่, คำอธิบายรายการ, รหัสบัญชี, เดบิต, เครดิต (หรือ จำนวนเงิน +เดบิต/−เครดิต), รหัสสาขา, หมายเหตุ
- แถวที่มีเลขที่รายการเดียวกันรวมเป็นสมุดรายวัน 1 รายการ ถ้าไม่มีเลขที่ ใช้วันที่ + คำอธิบายเดียวกัน และออกเลข JV ให้อัตโนมัติ
- วันที่รับ 2026-09-30, 30/09/2026 หรือ 30/09/2569 (พ.ศ.) · รหัสบัญชีต้องมีในผังบัญชีแล้ว (นำเข้าผังบัญชีก่อนถ้ายังไม่มี)
- ก่อนนำเข้าจะแสดงรายการที่แปลงแล้ว และดาวน์โหลดเป็น CSV เพื่อตรวจได้ รายการที่ไม่สมดุล ไม่พบบัญชี อยู่ในงวดที่ล็อก หรือเลขที่ซ้ำ จะถูกข้าม

### สำรองข้อมูล
- **ไฟล์สำรอง (ทุกแพ็กเกจ):** ฟันเฟือง → สำรองข้อมูลบริษัท ดาวน์โหลดไฟล์ `.json` ของบริษัทที่เปิดอยู่
  หน้าแรกจะเตือนเมื่อบริษัทมีเอกสารแต่ยังไม่เคยสำรอง หรือสำรองครั้งล่าสุดเกิน 7 วัน (ผู้ดูไม่เห็นคำเตือน)
- **กู้คืน:** ตั้งค่า → นำเข้าข้อมูล → กู้คืนจากไฟล์สำรองข้อมูล รายการที่มีรหัสเดียวกันจะถูกเขียนทับ
  ไม่กู้คืนวันที่ล็อกงวด และถ้ากู้คืนเข้าบริษัทอื่นจะไม่เขียนทับชื่อ/เลขผู้เสียภาษี/ข้อมูลนิติบุคคลของบริษัทนั้น
  รายการที่ระบบไม่ยอมให้บันทึก (อยู่ในงวดที่ล็อก, ไม่มีสิทธิ์, อ้างสาขาที่ถูกลบ) จะถูกข้ามและแจ้งจำนวน
- **สำรองอัตโนมัติฝั่งเซิร์ฟเวอร์ (แนะนำสำหรับข้อมูลจริง):** ต้องใช้แพ็กเกจ Blaze ตั้งใน Firebase/Google Cloud Console ไม่ต้องแก้โค้ด
  - Firestore → Disaster recovery → Backups: สร้างตารางสำรองรายวัน/รายสัปดาห์ (เก็บได้สูงสุด 14 วัน / 14 สัปดาห์)
  - Point-in-time recovery (PITR): ย้อนข้อมูลได้ถึง 7 วันที่ผ่านมา
  - การกู้คืนจาก backup ฝั่งเซิร์ฟเวอร์จะสร้างฐานข้อมูลใหม่ ไม่เขียนทับฐานข้อมูลเดิม

### ตรวจสอบเงินเดือนและข้อมูล ภ.ง.ด.1

ทีมงาน → เงินเดือน คำนวณภาษีหัก ณ ที่จ่ายจากเงินได้ประมาณทั้งปี (รายได้เดือนนี้ × 12) หักค่าใช้จ่าย 50% ไม่เกิน 100,000 บาท ค่าลดหย่อนส่วนตัว 60,000 บาท ประกันสังคม และค่าลดหย่อนอื่นของพนักงาน แล้วคิดภาษีอัตราก้าวหน้าและหาร 12 ผู้ใช้แก้ยอดภาษีได้ กรณีโบนัสครั้งเดียว เริ่ม/ออกงานระหว่างปี รายได้เปลี่ยน หรือปรับภาษีปลายปี ต้องตรวจและปรับยอดตามข้อมูลจริง สูตรนี้ไม่ได้ปรับยอดสะสมทั้งปีให้อัตโนมัติ

ปุ่ม **สรุปข้อมูล ภ.ง.ด.1 ตามเดือนที่จ่าย** แสดงรายได้และภาษีของรอบเงินเดือนที่ยังไม่ยกเลิก อิงวันที่จ่ายเงินจริง รวมรายการที่ไม่มีภาษีหัก พร้อมส่งออก CSV เพื่อประกอบการจัดทำแบบ ไม่ใช่ไฟล์สำหรับนำเข้า e-Filing และไม่ใช่การยื่นแบบอัตโนมัติ เลขผู้เสียภาษีและยอดในรายงานมาจากข้อมูลที่บันทึกไว้ในรอบเงินเดือน

การเปิดแก้รอบเดิมรักษายอดประกันสังคมและภาษีที่บันทึกไว้ เมื่อแก้รายได้หรือสั่งคำนวณใหม่จะใช้ค่าตั้งค่าปัจจุบัน กำหนดนำส่งที่แสดงเป็นวันทั่วไป ต้องตรวจวันหยุดและประกาศขยายเวลาที่ใช้กับงวดนั้นด้วย

รัน `npm run test:payroll` เพื่อตรวจขั้นภาษี เงินเดือนสุทธิ การรักษายอดเดิม ข้อมูล ภ.ง.ด.1 และการปฏิเสธยอดติดลบในเบราว์เซอร์แบบแยกข้อมูลทดสอบ

หากเบราว์เซอร์ของสภาพแวดล้อมไม่รองรับ `file://` ให้เปิด static server ของ checkout ที่ `127.0.0.1` แล้วตั้ง `TEST_LOCAL_ORIGIN` เป็น origin ของ server ก่อนรัน smoke/payroll/regression tests เช่น `http://127.0.0.1:8765` ชุดทดสอบยังแทนค่า Firebase ด้วย local storage หรือ demo emulator และไม่ใช้ฐานข้อมูลจริง

### แยกรายรับและรายการหักเงินเดือน

หน้าบันทึกเงินเดือนแสดงยอดสรุปต่อพนักงาน กด **แยกรายรับ / รายการหัก** เพื่อกรอกยอดเงินของรายรับ 14 ประเภทและรายการหัก 12 ประเภทตามสลิป รายการโอทีทั้งสามประเภทเป็นยอดเงินที่ผู้ใช้กรอก ไม่ได้คำนวณอัตราจากจำนวนชั่วโมงให้อัตโนมัติ เงินประจำตำแหน่ง ค่าประสบการณ์ ค่าวิชาชีพ และค่าครองชีพตั้งค่าเริ่มต้นต่อเดือนได้ในข้อมูลพนักงาน แล้วปรับในแต่ละรอบได้

- รวมรายรับ = เงินเดือน + รายรับอื่นทุกประเภท รวมเงินเบิกคืนจริง
- รวมรายการหัก = สาย + ลากิจ + ขาดงาน + พักงาน + ภาษี + ประกันสังคม + กองทุนสำรองเลี้ยงชีพ + เงินล่วงหน้า + เงินกู้ + เงินสงเคราะห์ลูกจ้าง + กยศ. + หักอื่น ๆ
- รับสุทธิ = รวมรายรับ − รวมรายการหัก

เบี้ยเลี้ยง ค่าอาหาร และค่าเดินทาง/ค่าเที่ยวตั้งต้นตามการใช้งานของบริษัทเป็น **เบิกคืนตามจริงพร้อมหลักฐาน** จึงไม่รวมฐานภาษีและประกันสังคม เงินโอทีรวมฐานภาษีแต่ไม่รวมฐานประกันสังคมเป็นค่าเริ่มต้น ปรับการรวมฐานรายรับแต่ละประเภทได้ที่ **เงินเดือน → ตั้งค่า** ให้ตรงลักษณะการจ่ายจริง เงินที่บันทึกเป็นสาย/ลา/ขาด/พักงานถือเป็นค่าจ้างที่ไม่ได้รับ ไม่ใช่ค่าปรับ หากมีรายการหักรูปแบบอื่นให้แยกเป็นหักอื่น ๆ

เงินล่วงหน้า เงินกู้ กยศ. เงินสงเคราะห์ และหักอื่น ๆ ลดเงินรับสุทธิ แต่ไม่ลดฐานภาษีโดยอัตโนมัติ กองทุนสำรองเลี้ยงชีพในรายการหักก็ไม่ลดฐานภาษีอัตโนมัติ: หากใช้สิทธิลดหย่อน ให้กรอกยอดต่อปีที่มีสิทธิจริงและไม่เกินเกณฑ์ใน **ค่าลดหย่อนภาษีอื่นต่อปี** ของพนักงาน โดยไม่กรอกซ้ำ สูตรภาษียังคงประมาณรายได้ที่อยู่ในฐานภาษีต่อเดือน × 12 กรณีโบนัส/รายได้ไม่สม่ำเสมอและการปรับปลายปีต้องตรวจและปรับภาษีเอง

บัญชีเงินล่วงหน้าและเงินกู้ใช้เครดิตลดลูกหนี้พนักงาน ส่วนกองทุน เงินสงเคราะห์ กยศ. และหักอื่น ๆ ใช้บัญชีค้างนำส่ง/ค้างจ่าย แยกเลือกบัญชีได้ในตั้งค่า หากยังไม่เลือก ระบบสร้างบัญชีให้เมื่อมีการหัก ต้องมีรายการจ่ายเงินล่วงหน้า/ให้กู้หรือยอดยกมาที่บัญชีเดียวกันไว้ก่อน ระบบไม่ได้จับคู่รายการเงินทดรองหรือสัญญาเงินกู้ให้อัตโนมัติ การนำส่งในหน้าเงินเดือนยังเป็นภาษีและประกันสังคม ส่วนกองทุนและรายการหักอื่นให้บันทึกการจ่ายตัดบัญชีค้างนำส่งตามจริง

สลิปและ CSV แสดงรายการครบ พร้อมรวมรายรับ รวมรายการหัก และสุทธิ รายงานประกอบ ภ.ง.ด.1 ใช้เงินได้ในฐานภาษีที่บันทึกไว้หลังหักค่าจ้างที่ไม่ได้รับ ไม่รวมเงินเบิกคืนที่ตั้งค่าไว้นอกฐานภาษี รายงานนี้ยังไม่ใช่ไฟล์นำเข้า e-Filing

รอบเดิมรักษายอดเดิมเมื่อเปิดหรือบันทึกโดยไม่แก้ตัวเลข ยอดหักขาด/ลารวมในข้อมูลเก่าแสดงเป็น **หักขาด/ลาเดิม** โดยไม่เดาว่าเป็นสาย ลา หรือขาดงาน เมื่อแก้รายการจะแปลงไปใช้รายละเอียดใหม่พร้อมพกยอดเดิมมาครั้งเดียว หากต้องการแยกยอดเดิมเป็นประเภทใหม่ ให้ลดยอดหักเดิมด้วยเพื่อไม่หักซ้ำ การแก้ตัวเลข/สั่งคำนวณใหม่ใช้ค่าตั้งค่าปัจจุบัน ส่วนภาษีที่เคยปรับเองคงยอดไว้จนกดคำนวณใหม่

### ปุ่มรายงานเงินเดือน ภาษี และการลา

ใน **ทีมงาน → เงินเดือน** มีปุ่มดูรายงานภายใน Accounting หกปุ่ม ไม่ต้องเชื่อมต่อบัญชี FlowAccount:

- **เงินเดือน/ค่าจ้าง** เลือกเดือนที่จ่ายเงินจริง ดูรายคน/เอกสาร เปิดสลิป ส่งออก CSV หรือดู/พิมพ์รายงาน
- **เอกสาร 50 ทวิ** เลือกปีภาษีและพนักงาน รวมเงินได้ในฐานภาษี ภาษีที่หัก ประกันสังคม และกองทุนสำรองเลี้ยงชีพ รวมพนักงานลาออกและผู้ที่ไม่มีภาษีหัก มีปุ่มเข้าได้จาก **ภาษี → หนังสือรับรอง 50 ทวิ** ด้วย โดยแยกจากเอกสารของผู้ขาย
- **เงินเดือน/ค่าจ้างสะสม** รวมตามรหัสพนักงานและวันที่จ่ายเงินจริงในปีที่เลือก กดดูรายละเอียดสะสมรายประเภทและประวัติการจ่ายได้ ไม่รวมรอบที่ยกเลิก
- **รายงานการลา** แสดงสิทธิ ใช้แล้ว รออนุมัติ และคงเหลือตามประเภท/ปี สิทธิที่ยังไม่กำหนดแสดงเป็น “ยังไม่กำหนดสิทธิ” ไม่เดาจำนวนวันตามกฎหมายหรือนโยบายบริษัท
- **รายละเอียดการลา** เพิ่ม/แก้วันเริ่ม วันสิ้นสุด จำนวนวันทำงานจริง (เต็มวัน/ครึ่งวัน) ประเภท รับ/ไม่รับค่าจ้าง และสถานะ รายการรออนุมัติแสดงแยก เฉพาะรายการอนุมัตินับใช้สิทธิ รายการไม่อนุมัติหรือยกเลิกยังเก็บประวัติไว้และไม่นับใช้สิทธิ
- **เอกสาร กท.20 ก** ข้อมูลประกอบการจัดทำแบบจากเงินเดือนรายปี/รายเดือน แสดงจำนวนผู้มีรายการเงินเดือน ไม่ถือว่าเดือนที่ไม่มีข้อมูลเท่ากับไม่มีลูกจ้าง ให้ระบุเลขบัญชีนายจ้าง รหัสกิจการ เพดานและอัตราตามข้อมูลที่ใช้ยื่นจริง และปรับค่าจ้างรายคนก่อนใช้ ระบบไม่ยืนยันว่าฐานภาษีเท่ากับค่าจ้างกองทุนเงินทดแทนและไม่เฉลี่ยเพดานตามระยะเวลาจ้างให้อัตโนมัติ เงินสมทบประมาณรวมคำนวณจากฐานรวมก่อนปัดเศษ ไม่ใช่ไฟล์ยื่นอัตโนมัติหรือแบบ กท.20 ก ที่ส่งให้สำนักงานประกันสังคมแล้ว

50 ทวิใช้ที่อยู่และเลขผู้เสียภาษีพนักงานจากข้อมูลพนักงาน แยกจากผู้ขายที่ชื่อเหมือนกัน เติมที่อยู่ใน **ทีมงาน → พนักงาน** และตรวจลำดับในแบบ ภ.ง.ด.1ก ให้ตรงกับแบบที่ยื่นก่อนบันทึกเอกสาร ฉบับบันทึกเก็บยอดและข้อมูลผู้จ่าย/ผู้รับไว้เป็น snapshot เมื่อเงินเดือนเปลี่ยนจะไม่แก้เอกสารเดิมเงียบ ๆ ต้องกด **โหลดข้อมูลเงินเดือนล่าสุด** แล้วบันทึกฉบับปรับปรุง โดยเก็บฉบับก่อนหน้าในประวัติ เอกสารที่ยังไม่บันทึกหรือแก้เลขที่/วันที่โดยยังไม่บันทึกแสดงเป็นร่าง ตรวจข้อมูลและยอดนำส่งก่อนลงนามใช้งานจริง

การลาเก็บแยกจากเอกสารบัญชีในข้อมูลบริษัท สำรอง/กู้คืนไปกับข้อมูลบริษัทได้ ไม่คำนวณวันลาจากยอดเงินที่หัก และไม่หักเงินเดือนอัตโนมัติ ให้บันทึกยอดเงินหักตามจริงในรอบเงินเดือนแยกกัน รายการลาคร่อมปีต้องแยกปีละรายการเพื่อจัดสรรวันและสิทธิให้ถูกต้อง กำหนดสิทธิรายคนรายปีรวมยอดยกมาที่ใช้ได้แล้ว ระบบไม่ยกยอดให้เอง ผู้ดูอ่านและส่งออกรายงานได้ แต่แก้การลา/สิทธิ/บันทึกเอกสารไม่ได้

รัน `npm run test:payroll-reports` เพื่อตรวจรายงาน ยอดสะสม ฉบับ 50 ทวิ การลา กท.20 ก การสำรองข้อมูล และการแยกบริษัท ชุด `test:rules` ตรวจสิทธิ์การอ่าน/เขียนข้อมูลการลาบน Firebase Emulator ด้วย
