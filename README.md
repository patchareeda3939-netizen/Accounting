# PSMacc — โปรแกรมบัญชีออนไลน์สำหรับธุรกิจไทย

เว็บแอปบัญชีแบบไฟล์เดียว (HTML + JavaScript ล้วน ไม่ต้องมีเซิร์ฟเวอร์)

## ความสามารถหลัก
- เอกสารขาย/ซื้อ: ใบเสนอราคา ใบสั่งขาย ใบแจ้งหนี้ ใบเสร็จ ใบลดหนี้ ใบวางบิล บิลซื้อ ค่าใช้จ่าย เช็คจ่าย
- ลงบัญชีคู่อัตโนมัติ สมุดรายวัน แยกประเภท งบทดลอง งบกำไรขาดทุน งบดุล และรายงานมาตรฐาน 80+ รายงาน
- ภาษี: ภ.พ.30 (VAT รอเรียกเก็บสำหรับค่าบริการ), หัก ณ ที่จ่าย, หนังสือรับรอง 50 ทวิ
- ธนาคาร: บัญชีหลายบัญชี, กระทบยอด, นำเข้า Statement (CSV/Excel/PDF) และจับคู่อัตโนมัติ
- ปิดงบรายเดือน, ยอดยกมาจากงบปีก่อน, หลายบริษัท/หลายสาขา, โครงการ/แผนก
- พิมพ์/PDF ฟอร์มเอกสาร (ต้นฉบับ/สำเนา), แนบไฟล์, อ่านใบเสร็จด้วย OCR (Tesseract)
- นำเข้า/ส่งออกข้อมูล Excel

## การเก็บข้อมูล
- ตั้งค่า **Firebase** แล้ว (ดูหัวข้อถัดไป): ต้องเข้าสู่ระบบ ข้อมูลเก็บบน Firebase ใช้ร่วมกันได้หลายคนจากทุกเครื่อง
- เปิดเป็น **Claude Artifact**: ข้อมูลเก็บในฐานข้อมูลของ Artifact ใช้ร่วมกันได้หลายคน
- เปิดเป็น **ไฟล์/GitHub Pages**: ข้อมูลเก็บใน localStorage ของเบราว์เซอร์เครื่องนั้นเท่านั้น
  ควรสำรองข้อมูลสม่ำเสมอ (ฟันเฟือง → สำรองข้อมูลบริษัท) และฟีเจอร์แนบไฟล์/อ่านเอกสารด้วย Claude ใช้ไม่ได้ในโหมดนี้

## ระบบ Login (Firebase)
เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน แต่ละบริษัทมีสิทธิ์ผู้ใช้ดังนี้
- **เจ้าของหลัก**: ผู้สร้างบริษัท มีสิทธิ์สูงสุด ไม่มีใครลดสิทธิ์หรือนำออกได้ เปลี่ยนได้ด้วยการ **โอนสิทธิ์เจ้าของหลัก** เท่านั้น (ต้องพิมพ์อีเมลผู้รับเพื่อยืนยัน)
- **เจ้าของ**: ทำได้ทุกอย่าง รวมถึงเชิญผู้ใช้และกำหนดสิทธิ์ (ยกเว้นเจ้าของหลัก) แต่ลบบริษัทหรือโอนสิทธิ์เจ้าของหลักไม่ได้
- **ผู้แก้ไข** (ฝ่ายบัญชี): สร้างและแก้ไขเอกสารและข้อมูลบัญชี รวมถึงข้อมูลใช้งานประจำวันของบริษัท แต่แก้ข้อมูลนิติบุคคลหลักไม่ได้
- **ผู้ดู**: ดูข้อมูลและรายงานได้อย่างเดียว

| ข้อมูล / การกระทำ | เจ้าของหลัก | เจ้าของ | ผู้แก้ไข (ฝ่ายบัญชี) | ผู้ดู |
|---|:-:|:-:|:-:|:-:|
| ข้อมูลนิติบุคคลหลัก: ชื่อบริษัท, ชื่อจดทะเบียน, เลขผู้เสียภาษี, สถานะ VAT, ประเภทนิติบุคคล, ที่อยู่ตามกฎหมาย, เดือนเริ่มรอบบัญชี | ✅ | ✅ | ❌ | ❌ |
| ข้อมูลใช้งานประจำวัน: ที่อยู่บนเอกสาร, โทร, อีเมล, เว็บไซต์, โลโก้, ข้อมูลติดต่อลูกค้า, ค่าเริ่มต้นเอกสาร/รายงาน | ✅ | ✅ | ✅ | ❌ |
| สาขา: เพิ่ม, แก้ชื่อ/ที่อยู่/โทร, ปิดใช้งาน/เปิดใช้งาน | ✅ | ✅ | ✅ | ❌ |
| สาขา: แก้รหัสหรือลบ สาขาที่ยังไม่มีประวัติ | ✅ | ✅ | ✅ | ❌ |
| สาขา: ลบสาขาที่มีประวัติ (รหัสสาขาที่มีประวัติแก้ไม่ได้ ใช้ปิดใช้งานแทน) | ✅ | ✅ | ❌ | ❌ |
| งวดบัญชี: ล็อกงวด (เลื่อนวันล็อกไปข้างหน้า) | ✅ | ✅ | ✅ | ❌ |
| งวดบัญชี: ปลดล็อก / ถอยวันล็อก | ✅ | ✅ | ❌ | ❌ |
| เชิญ/เปลี่ยนสิทธิ์/นำผู้ใช้ออก, ดูประวัติ (Audit Log) | ✅ | ✅ | ❌ | ❌ |
| โอนสิทธิ์เจ้าของหลัก, ลบบริษัท | ✅ | ❌ | ❌ | ❌ |

"สาขาที่มีประวัติ" คือสาขาที่มีเอกสาร (ใบกำกับภาษี ใบเสร็จ บิล ฯลฯ) อ้างอิงแล้ว ระบบทำเครื่องหมายให้อัตโนมัติเมื่อบันทึกเอกสาร และยกเลิกไม่ได้
การล็อก/ปลดล็อกงวดและการลบสาขาทุกครั้งถูกบันทึกในประวัติ พร้อมผู้ทำ วันเวลา และงวด/สาขา

**งวดบัญชีที่ล็อกแล้ว** บังคับที่ `firestore.rules` (ยิงตรงเข้า Firestore ก็ไม่ได้) สำหรับทุกบทบาท รวมถึงเจ้าของ:
เอกสารและแบบ ภ.พ.30 ที่ลงวันที่ในงวดที่ล็อก (วันที่ ≤ วันล็อก) สร้าง แก้ไข ยกเลิก ลบ หรือย้ายวันที่เข้า/ออกไม่ได้ ต้องให้เจ้าของปลดล็อกก่อน
ยกเว้นการรับ/จ่ายชำระที่ลงวันที่หลังวันล็อก ซึ่งบันทึกบนเอกสารเดิมได้ (เช่น รับชำระใบแจ้งหนี้เดือนที่ปิดแล้ว)
การชำระที่ลงวันที่ในงวดที่ล็อกเพิ่ม/ลบไม่ได้ ข้อจำกัด: ขณะมีการล็อก การเขียนหนึ่งครั้งเพิ่ม/ลบรายการชำระได้ไม่เกิน 10 รายการ
บังคับทั้งในหน้าเว็บและใน `firestore.rules`

ทุกการเปลี่ยนสิทธิ์ (สร้างบริษัท เข้าร่วมตามคำเชิญ เปลี่ยนสิทธิ์ นำออก โอนสิทธิ์) ถูกบันทึกใน **ประวัติการเปลี่ยนสิทธิ์**
พร้อมผู้ดำเนินการ ผู้ถูกเปลี่ยน สิทธิ์เดิม/ใหม่ และเวลาจากเซิร์ฟเวอร์ `firestore.rules` บังคับให้ทุกการเปลี่ยนแปลงต้องมีบันทึก
และบันทึกแก้ไขหรือลบไม่ได้ เจ้าของดูประวัติได้ที่ จัดการผู้ใช้

### ตั้งค่าครั้งแรก
1. สร้างโปรเจกต์ที่ https://console.firebase.google.com
2. **Authentication → Sign-in method** เปิด **Email/Password**
3. **Firestore Database → Create database** เลือก production mode
4. **Firestore Database → Rules** คัดลอกเนื้อหาไฟล์ `firestore.rules` ไปวางแทนของเดิม แล้วกด **Publish**
   (หรือใช้คำสั่ง `npx firebase-tools deploy --only firestore:rules --project <project-id>`)
5. **Project settings → Your apps → Add app (Web)** คัดลอกค่า `firebaseConfig` ไปใส่ใน `src/config.js` แล้วรัน `./build.sh`
6. ถ้าเผยแพร่บน GitHub Pages: **Authentication → Settings → Authorized domains** เพิ่ม `<ชื่อผู้ใช้>.github.io`

ค่าใน `src/config.js` เปิดเผยได้ ความปลอดภัยของข้อมูลมาจาก `firestore.rules` ต้อง Publish rules ทุกครั้งที่แก้ไฟล์นี้

### ไฟล์แนบ (Firebase Storage)
ไฟล์แนบของเอกสารเก็บใน Firebase Storage ที่ `companies/{บริษัท}/files/{id}` สิทธิ์ตาม `storage.rules`:
สมาชิกบริษัทเปิดดูได้, เจ้าของและผู้แก้ไขอัปโหลดได้ (รูปภาพ PDF CSV TXT JSON MD ไม่เกิน 20 MB), แก้ไขหรือลบไฟล์ไม่ได้ (เก็บเป็นหลักฐาน)
1. **Storage → Get started** (โปรเจกต์ใหม่ต้องใช้แพ็กเกจ Blaze จึงจะสร้าง bucket ได้ ยังมีโควตาใช้ฟรี) เลือก production mode
2. **Storage → Rules** คัดลอกเนื้อหาไฟล์ `storage.rules` ไปวางแล้วกด **Publish**
   ครั้งแรก Console จะขอสิทธิ์ให้ Storage อ่าน Firestore ได้ (ใช้ตรวจสมาชิกบริษัท) ให้กด Allow
   (หรือ `npx firebase-tools deploy --only storage --project <project-id>`)
3. ตรวจว่า `storageBucket` ใน `src/config.js` ตรงกับชื่อ bucket ในหน้า Storage
   แล้วเปลี่ยน `FIREBASE_STORAGE_ENABLED = true` ใน `src/config.js` และรัน `./build.sh` (ค่าเริ่มต้นเป็น `false` ปุ่มแนบไฟล์จะถูกซ่อน)
4. (ไม่บังคับ) ถ้าต้องการพรีวิว PDF/ไฟล์ข้อความในหน้าเว็บ ต้องเปิด CORS ของ bucket ด้วย Cloud Shell:
   ```
   echo '[{"origin":["https://<ชื่อผู้ใช้>.github.io"],"method":["GET"],"maxAgeSeconds":3600}]' > cors.json
   gcloud storage buckets update gs://<bucket> --cors-file=cors.json
   ```
   ถ้าไม่ตั้ง รูปภาพยังแสดงได้ ไฟล์อื่นจะมีลิงก์ "เปิดไฟล์ในแท็บใหม่" แทน

ถ้ายังไม่เปิด Storage (`FIREBASE_STORAGE_ENABLED = false`) ส่วนอื่นของแอปใช้งานได้ตามปกติ ปุ่มแนบไฟล์ถูกซ่อนและแสดงว่ายังไม่ได้เปิดใช้การแนบไฟล์

### การใช้งาน
- ผู้ใช้ใหม่สมัครสมาชิกแล้วสร้างบริษัทแรก ผู้สร้างเป็นเจ้าของบริษัท
- เจ้าของเชิญผู้ใช้จาก **ชื่อบริษัทมุมซ้ายบน → จัดการผู้ใช้** ระบบไม่ส่งอีเมลเชิญให้
  ต้องแจ้งผู้ใช้เองให้สมัครด้วยอีเมลที่เชิญและกดลิงก์ยืนยันอีเมล จากนั้นบริษัทจะปรากฏเมื่อเข้าสู่ระบบ
- ย้ายข้อมูลเดิมจากโหมดเบราว์เซอร์: ในโหมดเดิมใช้ ฟันเฟือง → สำรองข้อมูลบริษัท แล้วเข้าสู่ระบบ Firebase และใช้ กู้คืนจากไฟล์สำรองข้อมูล
- ผู้ดูเห็นข้อมูลแบบอ่านอย่างเดียว ปุ่มสร้าง/แก้ไข/ลบถูกซ่อน (และ firestore.rules ปฏิเสธการเขียนอยู่แล้ว)
- ข้อจำกัด: อ่านเอกสารด้วย Claude (OCR) ใช้ไม่ได้ในโหมดนี้, ไฟล์แนบที่กู้คืนเข้าบริษัทอื่นยังชี้ไปที่ไฟล์ของบริษัทเดิม (เปิดได้เฉพาะสมาชิกบริษัทเดิม),
  ทุกครั้งที่เปิดแอประบบจะอ่านข้อมูลทั้งบริษัท ควรตรวจสอบโควตาและค่าบริการของ Firebase เมื่อข้อมูลมาก

### สำรองข้อมูล
- **ไฟล์สำรอง (ทุกแพ็กเกจ):** ฟันเฟือง → สำรองข้อมูลบริษัท ดาวน์โหลดไฟล์ `.json` ของบริษัทที่เปิดอยู่
  หน้าแรกจะเตือนเมื่อบริษัทมีเอกสารแต่ยังไม่เคยสำรอง หรือสำรองครั้งล่าสุดเกิน 7 วัน (ผู้ดูไม่เห็นคำเตือน)
- **กู้คืน:** ตั้งค่า → นำเข้าข้อมูล → กู้คืนจากไฟล์สำรองข้อมูล รายการที่มีรหัสเดียวกันจะถูกเขียนทับ
  ไม่กู้คืนวันที่ล็อกงวด และถ้ากู้คืนเข้าบริษัทอื่นจะไม่เขียนทับชื่อ/เลขผู้เสียภาษี/ข้อมูลนิติบุคคลของบริษัทนั้น
  รายการที่ระบบไม่ยอมให้บันทึก (อยู่ในงวดที่ล็อก, ไม่มีสิทธิ์, อ้างสาขาที่ถูกลบ) จะถูกข้ามและแจ้งจำนวน
- **สำรองอัตโนมัติฝั่งเซิร์ฟเวอร์ (แนะนำสำหรับข้อมูลจริง):** ต้องใช้แพ็กเกจ Blaze ตั้งใน Firebase/Google Cloud Console ไม่ต้องแก้โค้ด
  - Firestore → Disaster recovery → Backups: สร้างตารางสำรองรายวัน/รายสัปดาห์ (เก็บได้สูงสุด 14 วัน / 14 สัปดาห์)
  - Point-in-time recovery (PITR): ย้อนข้อมูลได้ถึง 7 วันที่ผ่านมา
  - การกู้คืนจาก backup ฝั่งเซิร์ฟเวอร์จะสร้างฐานข้อมูลใหม่ ไม่เขียนทับฐานข้อมูลเดิม

### ทดสอบกับ Firebase Emulator
ตั้ง `FIREBASE_CONFIG` เป็นค่าใดก็ได้ที่มี `apiKey` และ `projectId: 'demo-psmacc'` และตั้ง `FIREBASE_EMULATOR_HOST = '127.0.0.1'` แล้วรัน
```
npx firebase-tools emulators:start --only auth,firestore,storage --project demo-psmacc
```

npm run build                     # ประกอบ dist/ และ index.html จาก src/

| คำสั่ง | ทดสอบอะไร | รหัส test case |
|---|---|---|
| `npm run test:smoke` | โหมดเบราว์เซอร์และโหมด Claude DB: เปิดทุกหน้า สร้าง/สลับบริษัท ไม่มี error | S-xx |
| `npm run test:rules` | `firestore.rules` ยิงตรงไปที่ฐานข้อมูล: ผู้ไม่ได้ Login, แยกข้อมูลหลายบริษัท (อ่าน/เขียน/ลบ), สิทธิ์ตามบทบาท, เจ้าของหลัก, โอนสิทธิ์, ห้ามเพิ่มสิทธิ์ตัวเอง, คำเชิญ, Audit Log, นำออก, field matrix ข้อมูลบริษัท, สาขา, ล็อกงวดบัญชี, บังคับงวดที่ล็อก | R1–R15 |
| `npm run test:regression` | bug ที่เคยพบจริงแต่ละตัว ต้องไม่กลับมา และการย้ายข้อมูลสาขาเดิม | REG-01–REG-14, MIG-01 |
| `npm run test:e2e` | ใช้งานจริงผ่านเบราว์เซอร์กับ Firebase Emulator: สมัคร Login Logout ลืมรหัสผ่าน เชิญ นำออก โอนสิทธิ์ | |
| `npm run check:dist` | ไฟล์ใน `dist/` และ `index.html` ตรงกับ `src/` (ลืมรัน build หรือไม่) | |

`test:rules`, `test:regression` และ `test:e2e` เปิด Firebase Emulator ให้เองด้วยโปรเจกต์จำลอง `demo-psmacc` ไม่แตะ Firebase จริง
ทุก push และ Pull Request จะรันชุดทดสอบนี้อัตโนมัติบน GitHub Actions (`.github/workflows/test.yml`)
**ถ้าแก้ `firestore.rules` ต้องให้ `npm run test:rules` ผ่านก่อน Publish ทุกครั้ง**
